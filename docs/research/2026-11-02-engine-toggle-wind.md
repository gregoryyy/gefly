## Start and stop are different APIs

The upstream [FGPropulsion.cpp](https://github.com/JSBSim-Team/jsbsim/blob/v1.3.3/src/models/FGPropulsion.cpp) binds global `propulsion/set-running` to `InitRunning(engineIndex)`. Zero means initialize engine 0 running; −1 initializes all engines running. It is **not a Boolean on/off switch**. Initialization also sets throttle and mixture commands/positions, invokes the engine's initialization routine and seeks a steady state. Calling it for an interactive restart is an explicit start assist with state side effects, not a modeled starter sequence.

The same source maps `propulsion/magneto_cmd` to piston magnetos and `propulsion/starter_cmd` to the selected engine(s)' starter flags. [FGEngine.cpp](https://github.com/JSBSim-Team/jsbsim/blob/v1.3.3/src/models/propulsion/FGEngine.cpp) separately exposes per-engine `propulsion/engine[0]/set-running` as a Boolean running-state accessor/setter. That actual flag is useful telemetry, but setting it false alone does not prevent the piston model from subsequently restarting.

[FGPiston.cpp](https://github.com/JSBSim-Team/jsbsim/blob/v1.3.3/src/models/propulsion/FGPiston.cpp), inspected in the pinned local build and [upstream raw source](https://raw.githubusercontent.com/JSBSim-Team/jsbsim/v1.3.3/src/models/propulsion/FGPiston.cpp), checks ignition, fuel and rotation each step. Magneto selection 0 removes spark; 3 selects both. A windmilling engine can regain running state with fuel, spark and sufficient RPM. Loss of combustion does not force the propeller to stop. Its initialization routine instead sets a running flag and a prescribed initial propeller speed. Native cranking applies starter torque; generic defaults fill missing starter parameters. The active engine XML supplies no starter-specific calibration, and the implementation omits battery/master-switch effects. None of this establishes installed starter or electrical fidelity.

The model calculates fuel flow from induction/mixture even when its running flag is false. Therefore positive fuel flow and rotating RPM do not, by themselves, prove combustion. Gate synthesized exhaust with the actual running state; retain independently derived propeller/mechanical and airframe-airflow components during windmilling. This is source-informed sound behavior, not an exhaust or windmilling acoustic calibration.

## Bounded command recommendation

Use a worker-owned on/off request, separate from mute. An off request should disable ignition and starter without directly zeroing RPM or inventing stopping torque. For on, prefer source-supported ignition/cranking with the running result read from the model; release starter according to the declared controller policy. If initialization assistance is used instead, label it and account for its throttle/mixture/RPM side effects. Do not imply a faithful magneto selector, battery, priming, starter-duty or aircraft checklist implementation.

Stage a paused request and apply it at the deterministic worker input boundary before the next step. Actual indications remain from the current physical state until the engine runs. Review is read-only and uses recorded actual running/rotation data and the distinct ignition request; this does not imply a separate cranking indication. Preserve collision locks and reject stale or malformed commands. A command request and actual running state may differ, so present them distinctly; a failed start must not receive an invented running indication.

## Wind means air-relative flow here

[FGAuxiliary.cpp](https://github.com/JSBSim-Team/jsbsim/blob/v1.3.3/src/models/FGAuxiliary.cpp) subtracts transformed atmospheric wind from body velocity and takes that air-relative vector's norm for true airspeed. Existing `tas_mps` therefore supports a bounded airflow-sound input without using groundspeed or inventing a weather-wind sensor. Airframe airflow can remain nonzero during an engine-off glide; a stationary aircraft in moving air is another reason to keep airflow separate from engine RPM.

Use an original filtered-noise component shaped by finite nonnegative TAS, with bounded gains and smoothing chosen for sound design. There is no sourced airframe acoustic transfer function, calibrated dB level, cockpit sealing/window model, gust spectrum or microphone measurement in this increment. Do not call the noise weather simulation or infer an aircraft limit from its gain curve. Missing engine telemetry can silence the engine component while valid independent airflow telemetry remains available; missing/invalid airflow must not retain stale noise indefinitely.

The follow-up requests a speed-dependent whistling component. An original bounded tone or narrow-band component whose frequency and gain follow actual TAS can meet that presentation request. Its frequencies, harmonics and gain envelope are sound-design choices, not measured C172 resonance, vortex-shedding, stall-warning or aerodynamic coefficients. Zero airflow must not leave a residual whistle, and engine-off glide may retain it. Verification should include rendered spectral peaks changing with TAS and silence at zero TAS, alongside the common playback/mute gates; no authentic aircraft-whistle or training-cue claim follows from those checks.
